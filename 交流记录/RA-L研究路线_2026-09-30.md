# 从当前工程原型走向 RA-L：研究定位与实施路线

日期：2026-09-30。状态：研究建议，尚未实施新算法或复现外部基线；不代表已经确认新颖性或能够录用。原有 demo 保持不变。

## 1. 诚实定位

当前已有一套 FAST-LIO2、动态感知、持久地图维护、局部感知、规划控制、仓库探索与地图保存的工程原型。它的价值在于能够观察和复现完整的机器人任务失败，而不只显示点云。

但自由空间清图、多地图视图、时序确认、A*/Dijkstra、frontier 探索、补扫与回环都不是凭组合便能成立的原创贡献。当前没有与外部强基线的同条件统计比较，不能称优于 FreeDOM、DUFOMap 或 Dynablox，也不能承诺 RA-L。

本轮重新核对源码：探索 launch 开启 evidence_only_clearing，稳定占用采用6次有效负证据；static_map_builder.cpp 的 updateEvidenceFreeSpace 使用扫描时间配对、射线与旧点距离、当前邻格回波保护和证据时效。它没有实现经过校准的逐体素删除概率或任务价值驱动的复查决策。exploration_coverage.py 当前根据已测表面的命中/方位不足生成补扫候选，而非判断哪个疑似失效占用最影响目标路线。探索运行器仍关闭 FAST-LIO 内置 dynamic_filter 和回环；bridge 地图更新不自动回写 FAST-LIO 内部匹配树。

历史记录保留短程成功、货架缺点、长程 RETURN_BLOCKED、覆盖不完整等结果。它们是研究线索，不是新方法已成立的证据。本轮未重新运行这些实验。

## 3. 推荐主线：任务驱动的疑似失效占用主动核验

暂定题目：面向稀疏激光观测的任务驱动地图核验与通道恢复。

核心问题：历史障碍可能已经离开，但稀疏扫描、遮挡和位姿误差使当前证据不足。机器人应何时保留占用、何时确认删除，以及是否值得移动到另一安全视角专门核验？

目标不是“地图看起来更干净”，而是：在匹配的静态误删水平和相同安全约束下，以更少观测/飞行代价恢复真实可通行路线。相比普通信息增益，优先解决影响当前目标、返航或关键通道的占用不确定性。

这只是候选贡献。三态地图、贝叶斯更新、序贯检验、信息增益、主动感知都已有研究；不能把这些术语组合后直接写成原创算法。必须说明具体证据模型、动作价值估计和计算方法与最近工作的实质差异。

### 3.1 最小方法设计

1. 分离三种情况：当前有占用支持、充分观测确认已空、证据不足待核验。待核验在执行碰撞检查中仍保守处理，不能为了找到路径直接放通。
2. 对每个历史占用保存可追溯证据：最近真实命中、有效穿透射线、时间、视角/基线、遮挡、几何误差范围和删除原因。未扫到、被遮挡、位姿不可靠均不等于自由。
3. 研究观测条件化的删除决策：区分同视角相关扫描与新增独立几何证据，纳入距离/入射角、采样覆盖和位姿误差。先用有真值数据校准；不能把固定权重换成“概率”名称就声称有概率保证。FAST-LIO 消息存在 covariance 字段不证明其数值已正确标定、时序匹配或涵盖漂移。
4. 从规划失败或明显绕路中识别值得核验的占用簇，不对整张地图逐点规划。保留障碍/假设障碍消失的两种地图仅用于估计任务价值，后者不能直接作为飞行执行地图。
5. 在当前可信可达自由空间里选核验视点，综合预期决策改善与飞行/观测成本；确认后更新地图并重新规划。无可达视点或预算耗尽时明确回退、绕行或报告未解决，不无限重试。

可作为设计起点的目标：

`V(q) = 预期任务代价下降(q) - 核验移动与等待代价(q)`

其中 q 必须满足独立碰撞和风险约束。真正难点是：如何不借助真值，预测该视点能否区分“障碍仍在”和“旧占用失效”，以及这种区分是否会改变可执行路线。若只以距离或可见点数加权，属于弱启发式基线而非已成立的新贡献。

当前人仍在时，它必须继续阻挡规划；“长期背景不保存人”与“现在可以飞穿人”是两回事。地图删除也不应绕过最新扫描的即时碰撞层。

### 3.2 与现有代码的衔接（待实施）

所有路径相对 AstraDrone_ros1_ws/src/SLAM/fastlio_bridge/：

| 位置 | 拟进行的工作 |
| --- | --- |
| src/static_map_builder.cpp | 先补删除/保留原因与逐体素证据记录，再新增可切换的证据模型；保留旧模式作基线 |
| scripts/exploration_coverage.py | 补扫证据与“占用存在性核验”分开，避免用已测表面分母替代全图覆盖 |
| scripts/warehouse_explorer.py | 增加核验目标选择、观察驻留、完成/失败和恢复原任务状态；保持航点单一发布者 |
| scripts/exploration_grid.py | 查询疑似占用对路线的影响；假设地图和执行地图分离；不降低机体/未知空间约束 |
| src/static_path_planner.cpp | 只有固定目标导航实验需要时接入相同核验接口，不误以为探索 demo 总是使用此规划器 |
| 新独立 launch/config/test | 研究配置、离线统一回放、闭环实验与自动评测；不直接覆盖旧演示参数 |

先不新增回环、语义大模型、多机或完整三维轨迹优化。若固定高度实验已能回答问题，就把范围明确限定为固定高度导航，而不是夸大为任意三维探索。

## 4. 先比较，再决定是否开发

阶段一：冻结当前版本和配置，补齐原始激光、IMU、位姿、TF、动态物体真值、地图修改、规划状态和时间基准记录。旧 ours 与新探索的清理策略不同，不能混称一个基线。研究开发前另行备份；本轮没有覆盖备份或创建分支。

阶段二：优先复现 FreeDOM、DUFOMap；先跑通作者数据/评测，再接本项目 MID360 输入，核对坐标、逐点时间、去畸变及传感器掩膜。相同扫描和位姿比较地图维护；校验是否使用未来扫描后才能列为因果在线基线。若接入在线需要包装，说明包装与作者原算法的边界。只有研究逐帧动态检测时再加 Dynablox。

阶段三：做小型失败边界实验。若作者方法在本项目合理工况下已经兼顾清理和静态保留，不人为破坏其参数制造 badcase；可以采用强基线作为系统底座，将研究集中到任务驱动主动核验。若连主动核验也没有稳定收益，则应调整选题。

阶段四：先实现可观测性/证据诊断，再实现最小核验模块。不要一开始改估计器、控制器和规划器全部组件；每个变量应能单独关闭。

阶段五：完成跨布局、跨轨迹和真实数据评估，再决定论文主张。不能通过换配置、减安全距离、丢弃失败样本或只展示好看的截图弥补方法不足。

## 5. 实验设计

场景至少覆盖：薄货架/叶片且机器人自运动；人先静止再离开；人离开但旧位置被遮挡；人根本没有离开；人停走/反向；少量鬼影封堵关键通道；无动态的正常环境。点密度、位姿误差、动态速度及遮挡分别控制，误差要包括相关偏差/漂移，不能只加独立高斯噪声。

分两层实验：

- 固定输入回放：各方法完全相同扫描和位姿，隔离地图维护能力。GT 位姿与真实估计位姿分开，用于区分算法问题和定位误差；不把旧输出话题回放当作重新运行算法。
- 闭环导航：相同世界、起点目标、控制器、安全阈值和环境事件协议，各方法独立运行。轨迹不同导致扫描不同，这是闭环结果的一部分，不能声称原始观测相同。环境变化按预先定义时序/事件触发，不专门照顾 ours；所有失败计入。

对照与消融：

1. 当前系统作为工程基线，不只采用关闭清理的弱 badcase。
2. FreeDOM/DUFOMap 配相同规划与控制接口，作为外部地图基线。
3. 删除决策模型 × 主动核验策略做独立消融。
4. 外部强地图基线也接同一个主动核验模块，验证收益来自哪里。
5. 主动策略比较不核验、相同预算随机/最近视点、普通信息增益、所提任务价值策略。
6. “真值静态图/真值占用纠正”只能作为注明的诊断参照，不作为可部署基线；固定规划器在真值地图上的结果也不必然构成任务性能上界。

先以至少3种布局、每种约10个成对种子建立试验框架，再依据离散程度决定统计规模；这不是 RA-L 要求或统计充分性的保证。按序列/任务统计均值、分位数、区间和失败率，避免把相邻帧当独立样本。调参场景与最终测试布局分开。

指标必须成对：

| 问题 | 核心指标 |
| --- | --- |
| 是否损坏静态地图 | 已观测静态表面保留率、真实障碍被误判为空的事件率 |
| 是否清除失效占用 | 有标签鬼影残留；从实际离开和从首次有效空闲证据开始的两种延迟 |
| 是否有助任务 | 通道恢复时间、到达率、停滞时间、总航程/时间（包含专门核验开销） |
| 是否完整 | 对独立可观测参考表面的覆盖，不只除以已经看到的表面 |
| 是否可部署 | 算法墙钟 P95/P99、CPU/PSS/峰值内存、队列积压/丢帧；Gazebo/RViz开销单列 |
| 是否更危险 | 真值碰撞/最小表面净空，静止人负例、薄结构误清；不只用人机中心距离 |

首选画“静态误删—清理延迟”“任务完成时间—核验代价”的权衡曲线，而不是挑一个阈值。若前端未改，ATE/RPE作为监测项，不把不同飞行轨迹下的误差变化归因为新的 LIO 方法。

## 6. 没有无人机实物时如何推进

现在即可完成公开真实数据回放、基线复现、可控仿真和误差敏感性实验。真实 MID360 手持/推车数据可验证稀疏采样、自运动和动态清图，但不能替代飞控闭环、振动、算力与安全验证。

若论文核心主张是无人机自主核验带来的任务收益，建议争取受控实机实验；这是对论证可信度的建议，不是“RA-L 一律必须真机”的投稿规则。没有实机时应缩小主张，并如实披露。涉及真实人员实验要按机构规则办理伦理/豁免及安全审查，不能为了演示要求人员近距离接触飞行无人机。

## 7. 判断继续还是换方向

继续条件：在匹配的静态保留/误删水平上，清理或通道恢复明显改善；改善能跨布局和真实数据复现；计入核验移动/等待后仍有任务收益；计算代价适合目标平台。

停止包装、重新选题的信号：只有地图更空；仅比关闭清理的 badcase 好；只能在一个仓库精调成功；优势来自缩小安全距离；强基线加相同补扫便完全抹平差异；收益小于随机波动。没有统一“提高某百分比就能录用”的门槛。

备选方向一：如果主动核验工作量过大，聚焦经过校准的、稀疏观测条件下的地图撤销决策。但需要证明超越 FreeDOM/DUFOMap 的保守性机制，不是只改阈值。

备选方向二：回环优化后的动态证据一致性，防止清除的人体在关键帧重建中复生。需要先可靠后端、关键帧/子地图证据绑定，并补查长期建图相关工作；当前后端历史有误回环，不建议作为第一选择。

轻量化可以作为支撑实验；单纯换 C++、降低显示频率、降采样通常属于工程优化。若要以此为论文主线，需新的增量表示/有界资源机制及保持质量的证据，另与 ROG-Map 等工作比较。

## 8. 论文该怎样组织

[RA-L 官方范围](https://www.ieee-ras.org/publications/ra-l/)强调创新研究思想及有意义的理论/应用结果，并非要求从零实现所有组件。采用 FAST-LIO2 等成熟底座是合理的；关键是新增部分能被清楚定义、归因和验证。

推荐一条论证主线：真实失败现象 → 不足证据导致地图/任务权衡 → 新的核验决策机制 → 公平基线和模块消融 → 真实数据与闭环任务证据 → 明确局限。

若实验支持，候选贡献可以是：一种面向任务关键失效占用的观测条件化核验决策；一个可复现的地图质量与通道恢复联合评测协议及数据。后者只有在协议/数据确有独特价值并公开到可复现程度时才能作为贡献，不能把常规实验清单单独包装为创新。

当前最值得做的第一步不是继续堆功能或写最终摘要，而是建立 FreeDOM/DUFOMap 与当前系统的同输入对照，并把“货架误删、人体先静止后离开、遮挡假墙”做成可重复实验。
