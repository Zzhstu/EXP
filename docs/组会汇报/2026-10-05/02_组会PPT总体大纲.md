# 组会 PPT 总体大纲与逐页制作指导

日期：2026-10-05。配套素材：同目录 `01_项目全量素材与PPT生成说明.md`（下文简称“素材稿”）。项目根目录 `/home/a/AstraDroneOpen`。

## 一、主题、受众与叙事目标

建议标题：**动态环境下无人机激光建图与自主探索：系统实现、地图维护和基线分析**。

副标题：基于 FAST-LIO2 的仓库仿真研究进展。

不要用“高精度完整自主建图系统”“全面优于 FreeDOM”“安全保证的无人机自主探索”等超出证据的标题。

面向机器人/SLAM 组会：假定听众知道点云、里程计和路径规划，但不熟悉本项目。原理讲到能够理解设计选择；参数、话题、测试日志和文献明细移入附录。

希望听众记住四点：

1. 动态环境的问题不仅是当前运动检测，更是历史占用如何持续影响无人机任务。
2. 我们已经搭建定位—感知—地图维护—规划—控制—探索—评测闭环，并做过真实仿真运行。
3. 内部对照有局部收益，但最新 FreeDOM 对照揭示静态结构维护不足；返航保存不等于完整建图。
4. 下一步聚焦可靠占用核验与任务相关复观测，而不是继续简单堆算法。

## 二、推荐规模与章节分配

默认 30 页主讲，约 38 分钟，另预留讨论时间。附录 12 页按需制作、不计入主讲时长。时间较短用第六节压缩方案。

| 章节 | 页码 | 约时长 | 主问题 |
|---|---|---:|---|
| 背景与研究对象 | S01–S05 | 5 分钟 | 为什么值得做，当前边界是什么 |
| 系统机制 | S06–S15 | 13 分钟 | 怎么运行，关键规则为何这样设计 |
| 实验与失败 | S16–S23 | 11 分钟 | 哪些改善有证据，哪些仍失败 |
| 文献、落地与研究计划 | S24–S30 | 9 分钟 | 和已有工作关系如何，下一步做什么 |

每页模板：一句结论标题 + 一张主图/一张小表 + 最多 3–4 条解释；底部放来源/版本/限制；讲稿可详细但不把整段素材塞进页面。

颜色建议：蓝=ours 主链；紫=FreeDOM/外部基线；橙=动态目标；红=风险/残影/失败；灰=静态背景；青=路径。不要所有失败都用浅灰藏起来。

## 三、逐页主讲大纲

### S01 封面：从“看见障碍”走向“维护可用地图”

- 核心内容：标题、副标题、汇报人/日期（姓名由用户填写，不虚构）、真实仓库截图。
- 图：已有仓库 Gazebo/RViz 图中选一张，查看后裁剪；不要生成虚构实验画面。
- 讲述：这是研究进展和基线分析，不是已经完成产品验收。
- 素材：第 1 节、图像资产列表。
- 时间：30 秒。

### S02 直观问题：人已经走开，规划器仍然绕着“墙”走

- 结论：地图中的过去会影响无人机现在的决策。
- 图：F01 三时刻问题示意；先展示旧点云，再展示路径绕行。
- 讲述：物体当前移动和物体过去留下的占用，是两个问题。
- 边界：标示意；不把示意图当实测地图。
- 时间：1 分钟。

### S03 我们研究的是三个相互关联的任务

- 三栏：动态感知 / 历史地图更新 / 地图支持导航探索。
- 每栏一个问题和一个指标，例如当前运动确认、旧 ROI 残留、通道恢复时间。
- 讲述：只展示检测球不能证明地图干净；图干净也不能证明导航安全。
- 素材：第 1.1、7.1 节。
- 时间：1 分钟。

### S04 实验平台与当前能力边界

- 场景：cangku 仓库、52 个货架、MID360 模拟雷达、PX4 SITL、可控行人。
- 当前范围：固定高度二维规划，维护三维点云；没有预载货架位置给 planner。
- 明示：主线无回环、无语义网络、未完成真机验证。
- 图：真实场景图 + 右侧能力/边界清单。
- 素材：第 1.2、3、4.2 节。
- 时间：1 分钟。

### S05 工作如何从功能打通走向可评测研究

- 图：F03 时间线。
- 重点节点：前端学习 → 动态感知 → 地图维护 → badcase/ours → 仓库探索 → FreeDOM 比较。
- 讲述：每步由上一阶段暴露的问题推动；回环失败和缺架不是删掉的旁支。
- 素材：第 2 节。
- 时间：1–1.5 分钟。

### S06 系统总架构：地图更新真正进入了任务链

- 图：F02；按定位、感知/地图、规划控制、评测四层画。
- 必须标 FreeDOM 旁路、真值只评测、回环关闭。
- 讲述：FreeDOM 输出地图但不控制飞行，后面比较不能错误归因。
- 素材：第 3 节。
- 时间：1.5 分钟。

### S07 FAST-LIO2 如何给出位姿与配准点云

- 图：F04；只保留一个点面残差公式。
- 解释：IMU 预测 + 激光约束校正，不是只对 IMU 双积分。
- 归属：已有 FAST-LIO2/ikd-Tree 方法，本项目采用而非重新发明。
- 素材：第 4.1 节、R01。
- 时间：1.5 分钟。

### S08 为什么“点变了”不一定是“物体动了”

- 图：F05 选两个时刻的 BEV/残差，对照非重复扫描示意。
- 三个原因：非重复采样、自运动/配准误差、遮挡变化。
- 结论：不能把新出现点当运动点，把没出现点当自由空间。
- 页脚：离线可视化，未运行 LMNet/SalsaNext；真实帧来自历史 example。
- 素材：第 4.2 节、E05、R02。
- 时间：1.5 分钟。

### S09 动态目标确认：从单帧差异到多帧证据

- 图：F06 候选—聚类—关联—确认链。
- 内容：运动轨迹一致性、静态支持否决、确认/退出滞回；显示与判定平滑分开。
- 讲述：为什么后期球消失可能是超范围/静止，而不一定节点停止；为什么确认有延迟。
- 不展示不存在的检测准确率。
- 素材：第 4.3 节。
- 时间：1 分钟。

### S10 多个地图视图，各自承担不同职责

- 图：一份持久体素存储分出 global/stable/local/free；旁边独立画前端 ikd-Tree。
- 结论：稳定人体仍可能成为旧占用，稳定不等于永久保留。
- 讲述：bridge cloud_map 更新不等于前端 ikd-Tree 被清理。
- 素材：第 3.2、4.4 节。
- 时间：1 分钟。

### S11 清理规则升级：旧占用何时才有资格被删除

- 图：F07 真实回波射线、端点保护、旧点与当前点。
- 主讲只保留三个条件：时空对齐、确实穿过旧占用、多次有效反证且当前无命中保护。
- 对比：旧轨迹擦除快但会伤静态；当前探索不允许运动假设直接授权删除。
- 限制：未复观测不能保证清除；仍可能误删/漏清。
- 素材：第 4.4 节。
- 时间：2 分钟。

### S12 地图更新如何改变路径，而不只是改变画面

- 图：F08 旧占用→局部更新→重新规划。
- 解释融合顺序、最新占用优先和有效旧路径的切换滞回。
- 结论：清图、重规划和当前碰撞检查应协调；只做斥力会陷入绕障不前进。
- 素材：第 4.5 节。
- 时间：1 分钟。

### S13 无人机自身尺寸与安全距离：不是越小越好

- 图：F09，主讲仅突出 0.40 m 机体、0.80 m 正常规划、恢复阈值不等同正常距离。
- 解释中心距离/桨尖间隙不同，动态风险另有预测。
- 结论：窄通道通过性与误差/制动余量有代价交换。
- 具体 CPA 公式放附录 A03。
- 素材：第 4.6 节。
- 时间：1 分钟。

### S14 自主探索：没有仓库先验，但不是没有任何假设

- 图：F11 前半部分 + 未知/自由/占用栅格示意。
- 解释可见未知收益、可达代价评分，真值不输入 planner；固定高度是限制。
- 结论：主动选目标，不是预写完整仓库巡航点；也不等于完整 FUEL。
- 素材：第 4.7 节、R20。
- 时间：1.5 分钟。

### S15 如何结束，以及为什么不能无限卡住

- 图：F11 后半部分，分别标收敛、预算返回、无安全退路、保存失败。
- 内容：从不安全起点恢复需要探索器与控制器共同确认；无进展显式失败。
- 结论：返航保存与地图完整度两个判据，不能只看 COMPLETE。
- 素材：第 4.8 节。
- 时间：1 分钟。

### S16 实验设计：先区分内部消融、外部基线和系统验证

- 表：E01 内部组合对照；E02 长程任务；E03 同轮外部地图；E04 回环负结果。
- 讲述：不同实验回答不同问题，不能跨配置混算成功率。
- 说明本次汇报使用已有实验产物，不是新一轮统一跑分。
- 素材：第 6、7 节。
- 时间：1 分钟。

- 左：作者方法思想，保守自由空间 + 扫描过滤/地图细化。
- 右：本地输入、旁路输出、独立保存；MID360 enhancement 关闭。
- 结论：它是实际迁移的外部地图基线，但不是论文完整复现，更不是导航替换。
- 图：F02 的旁路放大。
- 素材：第 5.2 节、R21。

### S21 同航线地图：FreeDOM 暴露了 ours 的静态结构不足

- 图：F13 同视角地图与局部货架，F14 总支持/最差支持小图。
- 核心数：90.92% vs 99.01%；29.59% vs 85.71%；10 vs 3 架低于 90%。
- 结论：此侧面代理指标 FreeDOM 更好，应正面承认并分析；两者均未通过逐架验收。
- 强制脚注：统一参考采样但输出密度不同，未测动态真值；地图点数不是排名。
- 素材：E03。

### S22 失败案例一：回环“成功”也能让轨迹更差

- 图：F15；只用在线轨迹报告口径。
- 核心数：ATE 0.0113→0.0478 m，接受 2 条回环；优化器无失败不代表约束正确。
- 结论：重复结构需要更强验证，因此当前主线关闭后端。
- 素材：E04。
- 时间：1 分钟。

### S23 失败案例二：安全停车与持续探索的接口冲突

- 图：旧“规划器不安全/控制器慢退或停住”冲突图→当前受限短退路+新扫描二次检查。
- 验证分层：单测/假飞控检查；一轮长程未再现首货架卡死；真实风险 1/2 分支与接触仍待验证。
- 结论：明确失败比无限卡住更可诊断，但不能宣称 bug 永不再现或零碰撞。
- 素材：第 4.8 节、E06。

### S25 当前工作的价值与证据边界

- 不做主观“综合性能雷达图”。
- 结论：平台价值明确，算法优越性和学术创新仍需更强证据。

## 五、图表和数据生成规范

### 5.1 数据源绑定

| 页 | 数据/图 | 输入依据 | 禁止混用 |
|---|---|---|---|
| S08 | F05 | E05 metadata/npz/PNG | 不标成网络预测结果 |
| S17 | F10 | E01 两个 metrics.json | 不换成仓库截图却保留 example 数字 |
| S19 | F12 | E02 result.json | 不把最后状态点数当导出 PCD 点数 |
| S21 | F13/F14 | E03 双 coverage.json、双对齐和 PCD | 不把 camera_init 与 map 直接叠加 |
| S22 | F15 | E04 原报告 | 不混最终 Path 重评数值 |
| S26 | 资源表 | E02 状态、源码 tick 统计窗口 | 不叫全系统延迟或 CPU 使用率 |

所有真实图表脚注使用短文件名；附录给完整项目相对路径。读数保留 2–3 位有效小数即可，源数据不改动。

### 5.2 机制图和实验图分离

- 机制示意：F01/F04/F06–F09/F11/F18 可以重绘，明确“示意”。
- 数据图：F10/F12/F14/F15 必须由现有结果读数生成，不凭总结文字编新样本。
- 点云截图：F13 必须从实际 PCD 正确对齐并统一视角；若本环境不能渲染，保留明确占位框和生成说明，不用 AI 图代替。
- 资源曲线：没有测试则仅显示测量计划；单个 P95 不能推导整条分布曲线。

### 5.3 用词校对表

| 推荐 | 避免 |
|---|---|
| 当前运动目标/历史失效占用 | 把所有人体都叫应删动态点 |
| 维护图、前端内部图、旁路图 | 三种图都简称“FAST-LIO 地图” |
| 同轮货架侧面支持代理指标 | 全仓真实三维完整率 |
| 返回并保存部分结果 | 自动等同“完全探索成功” |
| 内部组合消融、单次观察 | 公平外部 SOTA 对比、统计显著 |
| 无预训练网络依赖 | 已证明低功耗机载实时 |
| 阅读/借鉴/迁移/验证分别注明 | 所有论文都“学习并复现” |
| PCD 点云文件 | PCB 点云文件 |
| 受限恢复并有安全门控 | 保证不会撞/不会再有 bug |
